# JoyJourney --- คู่มืออัปเดตไฟล์จาก ZIP เข้า GitHub

เอกสารนี้อธิบายวิธีนำไฟล์โปรเจกต์ JoyJourney จาก ZIP ไปอัปเดตใน Repository
`project_Journey` บน Branch `feature/planner-places` ผ่านเว็บไซต์ GitHub
โดยพยายามรักษาไฟล์เดิมที่ไม่เกี่ยวข้องไว้

## 1. เป้าหมาย

-   อัปเดตไฟล์จากโปรเจกต์ ZIP เข้า Repository เดิม
-   เพิ่มไฟล์ใหม่ที่ยังไม่มีใน Repository
-   แทนที่เฉพาะไฟล์ที่ต้องการอัปเดตและอยู่ในตำแหน่งเดียวกัน
-   ไม่ลบไฟล์เดิมที่ไม่ได้อยู่ใน ZIP
-   ตรวจสอบตำแหน่งไฟล์ก่อน Commit ทุกครั้ง

> **ข้อควรระวัง:** เมื่ออัปโหลดไฟล์ที่มีชื่อและตำแหน่งเดียวกับไฟล์เดิม GitHub
> จะบันทึกเวอร์ชันใหม่ทับไฟล์เดิมใน Branch ที่เลือก ควรตรวจสอบไฟล์ก่อน Commit เสมอ

## 2. เตรียมไฟล์

1.  หาไฟล์ `JoyJourney-Cosmic (1).zip` ในคอมพิวเตอร์
2.  คลิกขวาและเลือก **Extract All...** เพื่อแตกไฟล์
3.  เปิดโฟลเดอร์ที่แตกออกมา เช่น `project_Journey-main`
4.  ตรวจสอบโครงสร้างไฟล์ก่อนเริ่มอัปโหลด
5.  อย่าอัปโหลด ZIP ทั้งก้อน และอย่านำโฟลเดอร์โปรเจกต์ไปวางซ้อนใน Repository
    โดยไม่ตั้งใจ

## 3. เลือก Repository และ Branch

1.  เปิด Repository `project_Journey` บน GitHub
2.  เลือก Branch `feature/planner-places`
3.  ตรวจสอบชื่อ Branch ให้ถูกต้องก่อนอัปโหลด
4.  เข้าโฟลเดอร์ปลายทางให้ตรงกับตำแหน่งของไฟล์ใน ZIP

## 4. โครงสร้างไฟล์ที่ควรตรวจสอบ

ตัวอย่างไฟล์และตำแหน่งที่อาจเกี่ยวข้องกับโปรเจกต์:

โครงสร้างนี้เป็นตัวอย่างสำหรับช่วยตรวจตำแหน่งไฟล์ ให้ยึดโครงสร้างจริงที่ปรากฏใน ZIP และ
Repository เป็นหลัก

## 5. วิธีอัปโหลดผ่านเว็บไซต์ GitHub

ทำทีละโฟลเดอร์:

1.  เข้าโฟลเดอร์ปลายทางใน Repository
2.  คลิก **Add file → Upload files**
3.  คลิก **choose your files** หรือลากไฟล์ลงในพื้นที่อัปโหลด
4.  เลือกเฉพาะไฟล์ที่ต้องการจากโฟลเดอร์ที่ตรงกันใน ZIP
5.  ตรวจรายชื่อไฟล์และตำแหน่งให้ถูกต้อง
6.  เลื่อนลงไปที่ **Commit changes**
7.  ใส่ข้อความ Commit เช่น `Update JoyJourney frontend`
8.  เลือก Commit ลง Branch `feature/planner-places` โดยตรง แล้วคลิก
    **Commit changes**

ถ้าไฟล์อยู่คนละโฟลเดอร์ ให้ทำแยกกันทีละโฟลเดอร์เพื่อหลีกเลี่ยงการวางไฟล์ผิดตำแหน่ง

## 6. ตำแหน่งไฟล์ที่ต้องระวัง

ชื่อไฟล์เดียวกันอาจอยู่คนละตำแหน่งและทำหน้าที่ต่างกัน เช่น:

-   `public/script.js` กับ `public/js/script.js`
-   `public/style.css` กับ `public/css/style.css`

อย่านำไฟล์จากตำแหน่งหนึ่งไปแทนอีกตำแหน่งโดยอัตโนมัติ ให้ตรวจว่าไฟล์ HTML
อ้างอิงไฟล์ใดอยู่ก่อน

## 7. แนวทางอัปโหลดตามส่วนของโปรเจกต์

  โฟลเดอร์/ไฟล์      แนวทาง
  ---------------- -------------------------------------------------
  `public/`        อัปโหลดหน้า HTML ที่ต้องการอัปเดต
  `public/js/`     อัปโหลด JavaScript ไปยังโฟลเดอร์ JavaScript เดิม
  `public/css/`    อัปโหลด CSS ไปยังโฟลเดอร์ CSS เดิม
  `server/`        ตรวจสอบก่อนแทนที่ เพราะอาจกระทบการทำงานของ Backend
  `database/`      ตรวจสอบ `schema.sql` ก่อนแทนที่
  `uploads/`       ตรวจสอบไฟล์ที่มีอยู่ก่อน หลีกเลี่ยงการเขียนทับไฟล์ผู้ใช้
  `README.md`      อ่านและเปรียบเทียบก่อนแทนที่คำอธิบายเดิม
  `.gitignore`     ตรวจสอบกฎเดิมก่อนเปลี่ยน
  `.env.example`   ตรวจสอบว่าไม่มีรหัสผ่านหรือคีย์ลับ

## 8. เช็กลิสต์ก่อน Commit

-   [ ] เลือก Branch `feature/planner-places` ถูกต้อง
-   [ ] อัปโหลดเฉพาะไฟล์ที่ต้องการ
-   [ ] ไฟล์อยู่ในโฟลเดอร์ปลายทางที่ถูกต้อง
-   [ ] ตรวจสอบชื่อไฟล์ซ้ำและตำแหน่งไฟล์ที่คล้ายกันแล้ว
-   [ ] ไม่ได้ลบไฟล์เดิมที่ไม่เกี่ยวข้อง
-   [ ] ไม่ได้อัปโหลดไฟล์ `.env` หรือข้อมูลลับ
-   [ ] ตรวจรายการไฟล์ที่ GitHub แสดงก่อน Commit

## 9. หลัง Commit

1.  กลับไปยังหน้า Repository และตรวจว่า Branch ยังเป็น
    `feature/planner-places`
2.  ตรวจรายการไฟล์และ Commit ล่าสุด
3.  ทดสอบหน้าเว็บและฟังก์ชันที่เกี่ยวข้อง
4.  หากพบปัญหา อย่ารีบลบไฟล์หรือเขียนทับเพิ่ม ให้ตรวจ Commit ล่าสุดก่อน

## หมายเหตุ

การอัปโหลดผ่านหน้าเว็บ GitHub ไม่ได้เปรียบเทียบเนื้อหาของไฟล์ใน ZIP
กับไฟล์เดิมให้อัตโนมัติว่าการแก้ไขใดจำเป็น ดังนั้นควรเลือกไฟล์อย่างระมัดระวัง โดยเฉพาะไฟล์
Backend, ฐานข้อมูล และไฟล์ตั้งค่าของระบบ
