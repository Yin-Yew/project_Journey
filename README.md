# JoyJourney

**ระบบวางแผนและจัดการการเดินทางร่วมกัน (Group Travel Planning and Management Web Application)**

JoyJourney เป็นเว็บแอปพลิเคชันสำหรับวางแผนทริปกับเพื่อน โดยรวบรวมข้อมูลการเดินทางไว้ในระบบเดียว ตั้งแต่การสร้างทริปและเชิญสมาชิก การวางตารางกิจกรรม การบันทึกสถานที่ การลงคะแนนเลือกจุดหมายครั้งต่อไป การหารค่าใช้จ่าย และการเก็บภาพความทรงจำ พร้อม **Checklist ส่วนตัว** ที่สมาชิกแต่ละบัญชีเห็นเฉพาะรายการของตนเอง

> **รุ่นอ้างอิง:** JoyJourney v12.2 (Clean — ไม่มีข้อมูล Demo)  
> **รูปแบบโครงงาน:** Full-stack Web Application / Academic Project  
> **Repository:** https://github.com/Yin-Yew/project_Journey  
> **สภาพแวดล้อมที่ทดสอบ:** Windows, เว็บเบราว์เซอร์บนคอมพิวเตอร์, Localhost และ MySQL

## 1. วัตถุประสงค์ของโครงงาน

การจัดทริปเป็นกลุ่มมักมีข้อมูลกระจายอยู่ในหลายช่องทาง เช่น ข้อความสนทนา ตารางเวลา โน้ต และบัญชีค่าใช้จ่าย JoyJourney จึงพัฒนาขึ้นเพื่อ

1. จัดการข้อมูลทริปและสมาชิกในพื้นที่เดียวกัน
2. วางกิจกรรมตามวันและเวลา และบันทึกสถานที่ที่ต้องการไป
3. สนับสนุนการตัดสินใจเลือกจุดหมายผ่านการโหวตแบบไม่แสดงชื่อผู้ลงคะแนน
4. บันทึก แบ่ง และติดตามค่าใช้จ่ายระหว่างสมาชิก
5. แยกรายการเตรียมสัมภาระเป็นข้อมูลส่วนตัวของแต่ละบัญชี
6. จัดเก็บภาพและคำบรรยายความทรงจำของแต่ละทริป

## 2. ฟีเจอร์หลัก

| ฟีเจอร์ | ความสามารถ |
| --- | --- |
| **Authentication & Profile** | สมัครสมาชิก เข้าสู่ระบบ ออกจากระบบ และแก้ไขข้อมูลบัญชี |
| **Dashboard** | สรุปทริปที่กำลังจะถึง สมาชิก งบประมาณ ค่าใช้จ่าย การชำระเงิน และความพร้อมในการจัดสัมภาระ |
| **My Trips** | สร้าง แก้ไข และจัดการทริป กำหนดช่วงวันเดินทาง งบประมาณ และสถานะ `Active` / `Finished` |
| **Trip Members** | เชิญเพื่อนด้วยรหัสหรือลิงก์เชิญ และแยกสิทธิ์ `Owner` / `Member` |
| **Planner** | บันทึกกิจกรรมรายวัน เพิ่ม แก้ไข และลบกิจกรรม โดยเรียงตามวันและเวลาอัตโนมัติ |
| **Places** | บันทึกสถานที่ท่องเที่ยว ร้านอาหาร หรือคาเฟ่พร้อมรูปภาพและรายละเอียดตามทริป |
| **Next Trip Vote** | เสนอจุดหมายและลงคะแนนแบบไม่แสดงชื่อผู้โหวต ตั้งช่วงเวลาเปิด–ปิด ดูเวลานับถอยหลัง และเก็บประวัติการโหวต |
| **Expenses & Payments** | บันทึกรายจ่าย แบ่งค่าใช้จ่ายแบบเท่ากัน/เปอร์เซ็นต์/กำหนดเอง ติดตามหนี้ และยืนยันการชำระเงิน |
| **Private Checklist** | จดรายการสัมภาระส่วนตัวของแต่ละบัญชี ติ๊กว่าเตรียมแล้ว แก้ไข และลบรายการ โดยผู้ใช้คนอื่นในทริปเดียวกันไม่เห็นข้อมูล |
| **Memories** | อัปโหลดภาพ เขียนคำบรรยาย และดูอัลบั้มตามทริป |
| **Settings** | เลือกธีมการแสดงผลและออกจากระบบ |

### ขอบเขตการใช้ข้อมูลร่วมกันและข้อมูลส่วนตัว

- **ข้อมูลร่วมในทริป:** ตารางกิจกรรม สถานที่ ค่าใช้จ่าย และอัลบั้มภาพ เป็นข้อมูลที่เกี่ยวข้องกับสมาชิกในทริปและอยู่ภายใต้เงื่อนไขสิทธิ์ของระบบ
- **Private Checklist (v12.2):** รายการผูกกับบัญชีผู้สร้าง ผู้ใช้แต่ละคนเพิ่ม ติ๊ก แก้ไข และลบได้เฉพาะรายการของตนเอง แม้เป็นสมาชิกทริปเดียวกัน เจ้าของทริปก็ไม่สามารถเปิดอ่านโน้ตส่วนตัวของสมาชิกคนอื่นผ่าน API นี้ได้
- **Next Trip Vote:** เป็นกระดานโหวตร่วมสำหรับผู้ใช้ที่เข้าสู่ระบบ ไม่ได้แยกหนึ่งโพลต่อหนึ่งทริป แต่ละบัญชีมีคะแนนที่ใช้งานได้หนึ่งคะแนนต่อรอบ และเปลี่ยนหรือถอนคะแนนได้ขณะเปิดโหวต ระบบแสดงคะแนนรวมโดยไม่แสดงรายชื่อผู้โหวต
- **Payments:** ระบบบันทึกยอดค้างจ่ายและการแจ้ง/ยืนยันรับเงิน **ไม่ใช่บริการโอนเงินจริงหรือช่องทางชำระเงินออนไลน์**

## 4. สถาปัตยกรรมระบบ

ระบบใช้รูปแบบ **Client–Server Architecture** โดยแยกการแสดงผล การประมวลผล และฐานข้อมูลออกจากกัน

```text
ผู้ใช้ผ่าน Web Browser
          │
          ▼
Frontend: HTML / CSS / JavaScript
          │ HTTP / REST API
          ▼
Backend: Node.js + Express
          │
          ├── ตรวจสอบการเข้าสู่ระบบและสิทธิ์ของผู้ใช้
          ├── ประมวลผลกฎทางธุรกิจของแต่ละฟีเจอร์
          └── รับ–ส่งข้อมูลผ่าน mysql2/promise
                              │
                              ▼
                         MySQL Database
```

ข้อมูลถูกส่งระหว่าง Frontend และ Backend ผ่าน REST API โดย Backend เป็นผู้ตรวจสอบสิทธิ์และเงื่อนไขการเข้าถึงข้อมูลก่อนดำเนินการกับฐานข้อมูล ไม่ใช้การซ่อนรายการบนหน้าเว็บเป็นมาตรการรักษาความเป็นส่วนตัวเพียงอย่างเดียว

## 6. การติดตั้งและเปิดใช้งาน (Windows / Localhost)

### 6.1 โปรแกรมที่จำเป็น

- **Node.js 20 ขึ้นไป** พร้อม npm
- **MySQL Server** (ใช้ MySQL 8 สำหรับการพัฒนาและทดสอบ)
- **Git** และ **Visual Studio Code** สำหรับจัดการซอร์สโค้ด (สามารถใช้เครื่องมืออื่นได้)

### 6.2 ดาวน์โหลดโปรเจกต์

เปิด PowerShell หรือ Terminal ในโฟลเดอร์ที่ต้องการเก็บโค้ด:

```powershell
git clone https://github.com/Yin-Yew/project_Journey.git
cd project_Journey
```

หากมี Repository อยู่แล้ว สามารถเปิดโฟลเดอร์นั้นใน VS Code ได้โดยตรง

### 6.3 ตั้งค่า MySQL

1. เริ่มการทำงานของ MySQL Server
2. สร้างไฟล์ `server/.env` จาก `.env.example` (หากยังไม่มีไฟล์ดังกล่าว):

   ```powershell
   Copy-Item .env.example server\.env
   ```

3. เปิด `server/.env` แล้วระบุค่าที่ตรงกับ MySQL บนเครื่องของตน เช่น

   ```dotenv
   PORT=3000
   DB_HOST=localhost
   DB_PORT=3306
   DB_USER=root
   DB_PASSWORD=YOUR_MYSQL_PASSWORD
   DB_NAME=joyjourney_clean
   ```

   เปลี่ยน `YOUR_MYSQL_PASSWORD` เป็นรหัสผ่านจริงบนเครื่อง **และห้ามนำไฟล์ `server/.env` ขึ้น GitHub** ชื่อฐานข้อมูล `joyjourney_clean` เป็นค่าเริ่มต้นของชุด Clean ไม่ใช่ชื่อฐานข้อมูลที่ทุกเครื่องต้องใช้เหมือนกัน

### 6.4 เปิดเซิร์ฟเวอร์

จากโฟลเดอร์หลักของโปรเจกต์ ให้รัน

```powershell
.\server\tools\SETUP-AND-START.bat
```

สคริปต์จะตรวจโปรแกรมที่ใช้งานพอร์ต 3000 ติดตั้งแพ็กเกจ Node.js เมื่อจำเป็น เตรียมฐานข้อมูล/ตาราง และเปิดเว็บเซิร์ฟเวอร์ **โดยไม่สร้างบัญชีหรือทริปตัวอย่างอัตโนมัติ**

เมื่อเซิร์ฟเวอร์เริ่มทำงาน ให้เปิดเบราว์เซอร์ที่

- สมัครสมาชิก: http://localhost:3000/register.html
- เข้าสู่ระบบ: http://localhost:3000/login.html
- ตรวจสถานะ API/ฐานข้อมูล: http://localhost:3000/api/health

หาก API พร้อมและฐานข้อมูลเชื่อมต่อได้ จะได้รับคำตอบลักษณะ `{"app":"JoyJourney","status":"ok","database":"connected"}`

> **การใช้ฐานข้อมูลเดิม:** สำรองข้อมูลก่อนอัปเกรดเสมอ สคริปต์ `setup-db.js` อาจปรับโครงสร้างตารางและมอบหมาย Checklist เก่ากลับให้บัญชีผู้สร้างตามกติกา v12.2 โดยไม่ตั้งใจลบรายการเดิม ทั้งนี้ควรตรวจ `DB_NAME` ให้ชี้ฐานข้อมูลที่ต้องการจริงก่อนรัน

## 7. วิธีใช้งานโดยสังเขป

1. **Register / Login:** สมัครบัญชีและเข้าสู่ระบบ
2. **Create Trip:** ที่ `My Trips` กด `Create Trip` ใส่ชื่อทริป จุดหมาย วันที่ งบประมาณ และภาพปก
3. **Invite Members:** เปิดหน้ารายละเอียดทริปแล้วคัดลอกรหัส/ลิงก์เชิญให้สมาชิกที่สมัครบัญชีแล้ว
4. **Planner:** เลือกทริป กด `Add Activity` ระบุวัน เวลา สถานที่ และรายละเอียด กิจกรรมจะแสดงตามเวลา
5. **Places:** เลือกทริปและบันทึกสถานที่พร้อมประเภท ภาพ และคำอธิบาย
6. **Next Trip Vote:** เพิ่มชื่อจุดหมาย กำหนดช่วงเวลา และให้สมาชิกเลือกหนึ่งคะแนนต่อบัญชีต่อรอบ โดยไม่แสดงชื่อคนโหวต
7. **Expenses:** บันทึกรายจ่าย เลือกผู้จ่าย ผู้ร่วมแบ่ง และรูปแบบการหาร จากนั้นติดตามยอดค้างจ่ายและสถานะยืนยันชำระ
8. **Checklist:** เลือกทริป พิมพ์ของที่ต้องเตรียม กด `Add` แล้วติ๊กเมื่อเตรียมเสร็จ รายการนี้เป็นของบัญชีที่ล็อกอินเท่านั้น
9. **Memories:** เลือกอัลบั้ม/ทริป อัปโหลดรูปและระบุ Caption
10. **Finish Trip:** เมื่อดำเนินกิจกรรมของทริปเสร็จแล้ว เจ้าของทริปสามารถเปลี่ยนสถานะเป็น `Finished`

## 8. ตัวอย่าง REST API

คำขอส่วนใหญ่ต้องเข้าสู่ระบบก่อน โดยส่ง Bearer token ที่ได้จากการ Login ตามรูปแบบ `Authorization: Bearer <token>`

| Method | Endpoint | รายละเอียด |
| --- | --- | --- |
| `POST` | `/api/auth/register` | สมัครสมาชิก |
| `POST` | `/api/auth/login` | เข้าสู่ระบบ |
| `GET` | `/api/auth/me` | ดูข้อมูลบัญชีที่เข้าสู่ระบบ |
| `GET`, `POST` | `/api/trips` | ดูรายการทริป / สร้างทริป |
| `POST` | `/api/trips/join` | เข้าร่วมทริปด้วยรหัสเชิญ |
| `GET`, `POST` | `/api/trips/:id/activities` | ดู / เพิ่มกิจกรรมในทริป |
| `GET`, `POST` | `/api/trips/:id/places` | ดู / เพิ่มสถานที่ในทริป |
| `GET`, `POST` | `/api/trips/:id/checklist` | ดู / เพิ่ม Checklist **ของบัญชีตัวเอง** |
| `PATCH`, `DELETE` | `/api/trips/:id/checklist/:itemId` | แก้ไข / ลบ Checklist ของบัญชีตัวเอง |
| `GET` | `/api/checklist/version` | ตรวจรุ่น API และบัญชีสำหรับ Private Checklist |
| `GET` | `/api/trips/:id/finance` | สรุปยอดการเงินของทริป |
| `POST` | `/api/trips/:id/expenses` | เพิ่มรายการค่าใช้จ่าย |
| `GET` | `/api/next-trip` | ดูข้อมูลรอบโหวตปัจจุบัน |
| `PUT`, `DELETE` | `/api/next-trip/vote` | ลงคะแนน / ถอนคะแนน |
| `GET` | `/api/next-trip/history` | ดูประวัติรอบโหวตแบบแสดงคะแนนรวม |
| `GET` | `/api/health` | ตรวจการทำงานของเซิร์ฟเวอร์และ MySQL |

รายละเอียด Endpoint อื่นและโครงสร้าง Request/Response ดูจากไฟล์ใน `server/` ซึ่งเป็นแหล่งอ้างอิงหลักของ API เวอร์ชันที่ใช้งาน

## 9. การทดสอบ

การทดสอบแบ่งเป็น **Automated Tests** และ **การทดสอบบน Localhost**

### Automated Tests

เมื่ออยู่ในโฟลเดอร์โปรเจกต์ สามารถรันชุดทดสอบดังนี้

```powershell
cd server
npm ci
npm test
```

ผลที่บันทึกในรายงาน Final Project สำหรับซอร์สโค้ด **v12.2** คือ **ผ่าน 51 จาก 51 รายการ** ผลนี้เป็นการทดสอบระดับโค้ดตามขอบเขตของชุดทดสอบ ไม่ใช่การรับรองสมรรถนะหรือความปลอดภัยของระบบบนอินเทอร์เน็ต

### การทดสอบผ่าน Localhost

ตามรายงานโครงงาน ผู้จัดทำทดสอบสถานการณ์หลัก **8 กรณี (T01–T08) และผ่านทั้งหมด** ครอบคลุมการสมัครและเข้าสู่ระบบ การสร้างทริปและเชิญสมาชิก การเรียงเวลาใน Planner การแยก Checklist ระหว่างสองบัญชี การโหวตและปิดรอบ การจัดการค่าใช้จ่าย ตลอดจน Memories และ Logout

การทดสอบข้ามบัญชีควรใช้บัญชีที่ต่างกันจริง เช่น บัญชีหนึ่งในหน้าต่างปกติ และอีกบัญชีหนึ่งในหน้าต่างไม่ระบุตัวตน (Incognito) โดยไม่ใช้ข้อมูลล็อกอินร่วมกัน

## 10. ความปลอดภัยและข้อจำกัด

**มาตรการที่ใช้ในระบบต้นแบบ**

- เก็บรหัสผ่านในรูปแบบแฮชด้วย `bcryptjs`
- ตรวจสอบ Bearer token ก่อนเข้าถึง API ที่ต้องล็อกอิน
- ตรวจบทบาท Owner / Member และความเป็นสมาชิกทริปจากฝั่ง Backend
- จำกัด Private Checklist ผ่านเงื่อนไข `trip_id` และ `assigned_to` โดยอิงบัญชีที่ผ่านการยืนยันตัวตน
- แยกข้อมูลกำหนดค่าฐานข้อมูลไว้ใน `server/.env` และกำหนด `.gitignore` เพื่อหลีกเลี่ยงการเผยแพร่ข้อมูลลับ

**ขอบเขตการประเมิน:** โครงงานได้รับการทดสอบบน Localhost แต่ยังไม่ได้ประเมินการรองรับผู้ใช้จำนวนมาก การใช้งานภายนอกเครือข่าย การทดสอบเจาะระบบ หรือความทนทานภายใต้โหลดสูงอย่างเป็นระบบ ก่อนนำขึ้นใช้งานสาธารณะควรเพิ่มมาตรการด้าน HTTPS การบริหารข้อมูลลับ การสำรองข้อมูล การตั้งค่าการเผยแพร่ และการทดสอบความปลอดภัยเพิ่มเติม

**ความหมายของการโหวตแบบไม่แสดงชื่อ:** ระบบต้องเก็บความเชื่อมโยงระหว่างบัญชีกับคะแนนในฐานข้อมูลเพื่อป้องกันการลงคะแนนซ้ำ แต่จะไม่ส่งชื่อผู้โหวตออกมาในหน้าผลคะแนนรวม
